# 首次使用：从集群注册到恢复验证

先按[安装指南](/docs/deployment/install)完成安装并登录。**在测试 Namespace 上验证完整流程后，再保护业务应用。**

## 1. 注册集群 {#register-cluster}

在顶部导航进入 **Configuration → Clusters**，选择注册操作和集群类型：Native Kubernetes、CCE 或 OpenShift。准备页面要求的 kubeconfig。

两种注册方式：

| 方式 | 适用条件 |
| --- | --- |
| **Install for me** | 平台注册执行器能访问集群 API |
| **Run command** | 平台无法直连集群，在一台能访问集群的主机上执行生成的命令 |

按页面第一步的说明准备文件，再执行当前生成的命令。**不要把访问 token 或 kubeconfig 分享到公开 issue。**

安装完成后确认集群状态为 online，节点和 Namespace 清单已上报。

::: warning 源集群和目标集群

保护流程需要源集群**和**目标集群。同一个集群是否适合作为恢复目标，需结合具体应用和恢复配置判断。

:::

## 2. 准备存储和策略 {#prepare-storage}

在 **Configuration** 中配置：

- **Storage**：对象存储地址、bucket 和凭据，确认集群侧可访问存储。
- **Policies**：保护计划和保留等选项。

也可以在新的保护向导中创建这些资源：向导与管理页复用创建界面，成功后重新加载并选中新增记录。

::: danger 保存成功只说明记录已写入

存储配置保存成功，只说明记录已写入数据库。访问权限和数据路径需要一次实际备份和恢复来验证。

:::

## 3. 配置应用保护 {#configure-protection}

进入 **DR → Application DR**。页面分三个阶段展示可保护的源应用、保护配置和目标侧恢复状态。

选择源 Namespace，启动保护向导，依次选择范围、目标、存储和策略。

多 Namespace 时按业务需要选择独立或合并。**多个应用有各自的恢复范围，不能当作一个 Namespace 处理。**

## 4. 核验备份和恢复 {#verify}

| 检查项 | 位置 | 检查内容 |
| --- | --- | --- |
| 任务执行 | Backup & Recovery Tasks | 执行状态及详情，失败时查看错误和日志 |
| 恢复点 | Restore Points | 是否产生了预期的恢复点，状态是否可用 |
| 恢复演练 | Drill | 在隔离范围验证恢复 |
| 应用校验 | 集群侧 | 工作负载、PVC 和应用数据，不能只看任务成功状态 |

恢复点可用的条件有三项：未处于创建中，源集群与保护配置仍能对应，对象存储当前可访问。任一项不满足时，不要启动恢复。

在 **DR → Restore Points** 选中恢复点后，用 **Drill** 验证。演练需要检查工作负载、PVC、Service 和应用数据，目标 Namespace 与网络必须与生产恢复计划隔离；**操作名称不保证目标自动隔离**。

::: tip Drill 与 Takeover 的区别

Drill 失败只影响演练，修正后可以重新执行；Takeover 执行后即为业务切换，必须先通过校验和变更审批。已核验恢复点的操作入口只有 Drill 和 Takeover，没有单独的 Restore 创建按钮。

:::

执行实际 Recovery 前，核对目标与资源映射，避免覆盖现有业务。

Dashboard 区分**平台概览**与**所选集群概览**；集群选择和时间范围决定指标范围，不能将所有指标都视为平台总量。任务失败时查看错误和日志，不要用示例数据说明结果。

## 5. 用户设置与清理 {#settings}

登录页固定使用深色主题，首次登录默认使用浅色主题。用户主题偏好保存在服务端，后续登录采用个人设置。用户显示的时间使用选定时区，服务端时间和调度使用 UTC。

测试完成后，删除或停用测试用的保护配置，避免继续产生备份流量、占用存储。

## 完成标准

- [ ] 集群状态 online，资源清单完整
- [ ] 存储连通性通过真实备份验证
- [ ] 至少一个应用保护配置处于运行状态
- [ ] 任务列表中有成功记录，恢复点可见
- [ ] 演练恢复后，工作负载和 PVC 校验通过

五项全部确认后，再开始保护业务集群。
