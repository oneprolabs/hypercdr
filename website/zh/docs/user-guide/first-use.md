# 首次使用：从集群注册到恢复验证

先按[安装指南](/docs/deployment/install)完成登录。**使用测试 namespace 验证完整流程后，再保护业务。**

## 1. 注册集群 {#register-cluster}

进入顶部 **Configuration → Clusters**，选择注册操作与集群类型：Native Kubernetes、CCE 或 OpenShift。准备页面要求的 kubeconfig。

两条注册路径：

| 路径 | 适用条件 |
| --- | --- |
| **Install for me** | 平台注册执行器能访问集群 API |
| **Run command** | 平台无法直连集群，在一台能访问集群的主机上执行生成的命令 |

按页面第一步准备文件，再执行当前生成的命令。**不要把访问 token 或 kubeconfig 分享到公开 issue。**

安装完成后确认：集群状态为 online，节点和 namespace 清单已上报。

::: warning 源集群和目标集群

保护流程需要源集群**和**目标集群。同一个集群是否适合作为恢复目标，需结合具体应用和恢复配置判断。

:::

## 2. 准备存储和策略 {#prepare-storage}

在 **Configuration** 中配置：

- **Storage**：对象存储地址、bucket 和凭据，确认集群侧可访问存储。
- **Policies**：保护计划及保留等选项。

也可以在新的保护向导中创建这些资源——向导与管理页复用创建界面，成功后重新加载并选中新增记录。

::: danger 不要只看保存成功

存储配置保存成功不代表存储可用。**实际备份与恢复才验证访问权限和数据路径。**

:::

## 3. 配置应用保护 {#configure-protection}

进入 **DR → Application DR**。页面三阶段分别展示：可保护的源应用、保护配置、目标侧恢复状态。

选择源 namespace，启动保护向导，依次选择范围、目标、存储和策略。

多 namespace 时按业务需要选择独立或合并。**不要把多个应用的恢复范围误认为同一 namespace。**

## 4. 核验备份和恢复 {#verify}

| 检查项 | 位置 | 看什么 |
| --- | --- | --- |
| 任务执行 | Backup & Recovery Tasks | 执行状态及详情，失败时看错误和日志 |
| 恢复点 | Restore Points | 是否产生了预期的恢复点 |
| 恢复演练 | Drill | 在隔离范围验证恢复 |
| 应用校验 | 集群侧 | 工作负载、PVC 和应用数据，而非任务成功标签 |

实际 Recovery 之前核对目标与资源映射，避免覆盖现有业务。

Dashboard 区分**平台概览**与**所选集群概览**；集群选择和时间范围用于对应指标，不能把所有指标都理解为平台总量。任务失败时查看错误和日志，不要用示例数据解释结果。

## 5. 用户设置与清理 {#settings}

登录页固定深色；首次登录默认浅色。用户主题偏好保存到服务端，后续登录采用个人设置。用户显示时间使用选定时区，服务端时间与调度基础使用 UTC。

测试完成后，删除或停用测试用的保护配置，避免它们继续产生备份流量占用存储。

## 完成标志

- [ ] 集群状态 online，资源清单完整
- [ ] 存储连通性通过真实备份验证
- [ ] 至少一个应用保护配置处于运行状态
- [ ] 任务列表里有成功记录，恢复点可见
- [ ] 演练恢复后，工作负载和 PVC 校验通过

五项都打勾，再开始保护业务集群。
