# 使用手册

这里按**功能模块**组织，适合已经上手、需要查具体操作的人。如果这是你第一次使用，先看[首次使用](/docs/user-guide/first-use)走一遍完整流程。

## 从零到恢复：推荐顺序

第一次把平台用起来，按这个顺序走不会卡住：

1. 完成安装并打开中控地址（[安装详解](/docs/deployment/install)）；
2. 登录后修改初始密码，确认组织与认证方式；
3. 注册源集群和目标集群，确认 Agent 在线；
4. 配置对象存储并测试连接；
5. 创建保护策略和应用保护配置；
6. 执行一次同步/备份，确认恢复点可用；
7. 在隔离环境执行 Drill，检查应用和数据；
8. 需要验证恢复时执行 Drill；正式接管走 Takeover，并在任务详情里完成验收。

> 列表里的「成功」只表示平台任务链路走完。生产验收仍要检查 Pod、PVC、Service、应用健康状态和实际数据。

## 模块地图

| 模块 | 解决什么问题 | 前置依赖 |
| --- | --- | --- |
| [仪表盘](/docs/manual/dashboard) | 平台和集群现在什么状态 | 至少一个集群在线 |
| [集群注册与管理](/docs/manual/clusters) | 把集群接入平台 | 可用的 kubeconfig |
| [对象存储](/docs/manual/storage) | 备份数据写到哪里 | 可访问的 S3 兼容存储 |
| [保护策略](/docs/manual/policies) | 什么时候备、备多久 | 存储已配置 |
| [应用容灾保护](/docs/manual/application-dr) | 哪些应用受保护、恢复到哪 | 集群 + 存储 + 策略 |
| [任务与恢复点](/docs/manual/tasks) | 备份到底成没成 | 已触发的保护任务 |
| [容灾演练](/docs/manual/drill) | 备份是否真的能恢复 | 存在恢复点 |
| [卸载集群 Agent](/docs/manual/agent-uninstall) | 下线一个集群 | Agent 命名空间可访问 |

## 依赖顺序

```text
集群 + 存储 + 策略  →  应用容灾保护  →  任务  →  恢复点  →  演练 / 恢复
```

前三个是基础资源，缺一个都建不起保护配置。基础资源可以在各自的管理页创建，也可以在保护向导里顺带创建。

## 贯穿全文的三条原则

::: warning 一、保存成功 ≠ 可用

存储配置、策略、保护配置保存成功只说明数据库写进去了。真正的可用性只有实际备份和恢复能证明。

:::

::: warning 二、任务成功 ≠ 恢复可用

任务状态反映执行流程是否走完。恢复能不能用，要看演练时工作负载、PVC 和应用数据的校验结果。

:::

::: warning 三、平台管理员 ≠ 组织成员

业务资源严格按组织隔离。平台管理员能管理用户和组织，但业务页面看到的仍然是自己所属组织的数据。

:::

## 日常运维

- 每日检查各集群 Agent 是否 online、对象存储是否可用、最近恢复点的时间；
- 定期在隔离环境执行 Drill，记录应用与数据的验收结果；
- 平台升级前备份 PostgreSQL、`.env`、`HCDR_SECRET_KEY`、TLS 文件和版本清单；
- 任务失败时先保留任务 ID、时间、集群版本和**首个**错误事件，再排查；
- 分享支持包和日志前，删除其中的 Token、密码、kubeconfig、密钥和内部地址。
