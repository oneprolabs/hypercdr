# 使用手册

本板块按功能模块组织，供完成安装后查询具体操作时使用。首次使用请先按[首次使用](/docs/user-guide/first-use)走完一遍完整流程。

## 推荐操作顺序

首次配置建议按以下顺序进行：

1. 完成安装并打开控制台（[安装详解](/docs/deployment/install)）；
2. 登录后修改初始密码，确认组织与认证方式；
3. 注册源集群和目标集群，确认 Agent 处于 online 状态；
4. 配置对象存储并测试连接；
5. 创建保护策略和应用保护配置；
6. 执行一次同步或备份，确认生成可用恢复点；
7. 在隔离环境执行 Drill，检查工作负载、PVC 和应用数据；
8. 需要正式接管时走 Takeover，并在任务详情中完成验收。

> 任务列表中的成功状态只表示平台侧执行流程结束。生产验收仍需检查 Pod、PVC、Service、应用健康状态和实际数据。

## 模块与依赖

| 模块 | 用途 | 前置条件 |
| --- | --- | --- |
| [仪表盘](/docs/manual/dashboard) | 查看平台与集群当前状态 | 至少一个集群在线 |
| [集群注册与管理](/docs/manual/clusters) | 将集群接入平台 | 可用的 kubeconfig |
| [对象存储](/docs/manual/storage) | 配置备份数据的写入位置 | 可访问的 S3 兼容存储 |
| [保护策略](/docs/manual/policies) | 定义备份计划与保留规则 | 存储已配置 |
| [应用容灾保护](/docs/manual/application-dr) | 定义受保护应用与恢复目标 | 集群、存储、策略 |
| [任务与恢复点](/docs/manual/tasks) | 查看备份执行结果 | 已触发的保护任务 |
| [容灾演练](/docs/manual/drill) | 验证恢复点是否可用 | 存在可用恢复点 |
| [卸载集群 Agent](/docs/manual/agent-uninstall) | 从平台下线集群 | Agent Namespace 可访问 |

依赖顺序如下：

```text
集群 + 存储 + 策略  →  应用容灾保护  →  任务  →  恢复点  →  演练 / 接管
```

前三项是基础资源，缺少任意一项都无法创建保护配置。基础资源可以在各自的管理页创建，也可以在保护向导中一并创建。

## 使用前提

配置和使用平台时，有三条前提需要始终记住。

::: warning 保存成功只表示配置已写入

存储、策略和保护配置保存成功，只说明记录已写入数据库。是否真正可用，需要一次实际备份和恢复来确认。

:::

::: warning 任务成功不等于恢复可用

任务状态反映执行流程是否结束。恢复能否使用，取决于演练时对工作负载、PVC 和应用数据的校验结果。

:::

::: warning 平台管理员不跨组织访问业务资源

业务资源按组织隔离。平台管理员可以管理用户和组织，但在业务页面中看到的仍是自己所属组织的数据。

:::

## 日常维护

- 每日检查各集群 Agent 是否 online、对象存储是否可用，以及最近恢复点的时间；
- 定期在隔离环境执行 Drill，记录应用与数据的验收结果；
- 平台升级前备份 PostgreSQL、`.env`、`HCDR_SECRET_KEY`、TLS 文件和版本清单；
- 任务失败时先记录任务 ID、时间、集群版本和首个错误事件，再开始排查；
- 分享支持包和日志前，删除其中的 Token、密码、kubeconfig、密钥和内部地址。
