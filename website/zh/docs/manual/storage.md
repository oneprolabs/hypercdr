# 对象存储

入口：**Configuration → Storage**。

备份数据不写在控制面主机上，而是写入你配置的对象存储。控制面数据库只记录元数据和任务状态，两者的生命周期相互独立。

## 需要准备的信息

| 项目 | 说明 |
| --- | --- |
| 端点地址 | S3 兼容服务的访问地址 |
| Bucket | 用于存放备份数据的存储桶 |
| 凭据 | 访问密钥与密钥，建议使用最小权限的专用账号 |
| 区域 | 部分服务需要显式指定 |
| 证书 | 自签名证书需要集群侧信任对应 CA |

## 配置步骤

1. 在 Storage 页新建存储配置，填入端点、bucket 和凭据。
2. 保存后确认关联到正确的集群——存储的可达性是**从集群侧**判断的，不是从控制面主机判断。
3. 在保护向导或应用容灾配置中选择这个存储。
4. 触发一次真实备份，确认数据落到目标 bucket。

::: tip 也可以在向导里创建

保护向导与管理页复用同一套创建界面。向导里创建成功后，页面会重新加载并选中新增记录。

:::

## 判断存储是否真的可用

保存成功只说明配置写进了数据库。以下才是证据：

- [ ] 备份任务成功，且耗时与数据量相符
- [ ] 目标 bucket 中能看到对应的对象
- [ ] 从该恢复点做过一次恢复，数据完整
- [ ] 集群侧网络策略允许访问存储端点

::: danger 不要用"保存成功"验收存储

存储不通的表现往往延迟到第一次备份才暴露，而那时可能已经过了保护窗口。装完环境就立刻跑一次真实备份。

:::

## 常见问题

| 现象 | 检查方向 |
| --- | --- |
| 任务报存储访问失败 | 凭据是否失效、bucket 是否存在、策略是否允许写入 |
| 部分集群成功、部分失败 | 各集群到存储端点的网络策略不同 |
| TLS 证书错误 | 集群侧是否信任自签 CA |
| 备份很慢 | 带宽、跨区域访问、存储限流 |
| 恢复点存在但恢复失败 | 存储凭据在恢复时是否仍有效 |

## 与保留策略的关系

存储不是无限空间。策略里配置的保留规则决定恢复点能留多久，过期恢复点会被清理。规划容量时按"数据量 × 保留份数 × 集群数"估算，并留出增长余量。
