# 邮件服务

入口：**Settings → Email Service**。需要平台管理员账号。

邀请成员、邮箱验证、密码找回这几类邮件都通过这里配置的 SMTP 投递。没配置时，相关页面会直接提示无法发送邮件。

::: warning 保存成功、测试成功、真收到，是三件事

配置保存成功只说明参数写进了数据库；测试成功只说明当前这一刻能连上邮件服务器。收件人能否收到，还要看对方邮件服务商是否拦截。这三步要分别确认。

:::

## 配置前准备

- 邮件服务器地址、端口、加密方式、认证用户名和密码（部分服务商要求专用授权码，不能直接用登录密码）；
- 一个获准使用的发件地址，通常需要先在邮件服务商侧完成域名或地址验证；
- 一个能收信的测试邮箱，最好覆盖内外部两种域名；
- 平台公开地址已填对。地址不对时，邮件能发出去，但里面的邀请链接或重置链接点开是错的。

## 新建配置

1. 进入 **Settings → Email Service**，点击 **New**。
2. 填写配置名称、SMTP Server、Port、Encryption、Username、Password、Sender Name、Sender Email。
3. 点击 **Create Configuration** 保存。
4. 在列表中选中这条配置，通过 **More → Test** 输入收件邮箱，发送测试邮件。
5. 查看列表里的 **Test Status** 和收件箱。没收到时，同时检查垃圾箱和邮件服务商的投递记录。
6. 需要用它做默认投递时，选 **More → Set as Default**，确认列表上的默认标识。

![新增 SMTP 配置窗口](/images/user-guide/email-new.png)

截图为未填写的创建窗口局部，Sender Email 等字段要在窗口内向下滚动才能看到。图中的 `587` 和 STARTTLS 是表单初始值，不代表你的邮件服务商要求这个组合。

## 字段说明

| 字段 | 说明 |
| --- | --- |
| Configuration Name | 便于识别的用途名称，不是服务器域名 |
| SMTP Server / Port | 邮件服务商提供的主机和端口，必须与加密方式匹配 |
| Encryption | STARTTLS、TLS 或 None；生产环境优先用服务商支持的加密连接 |
| Username / Password | SMTP 认证信息，可能需要专用授权码；不要沿用示例值 |
| Sender Name | 收件人看到的发件人名称 |
| Sender Email | 收件人看到的发件地址，需满足服务商的授权规则 |
| Test Status | Not tested、Succeeded 或 Failed，反映最近一次测试结果 |
| Default | 默认投递配置，不只是一个排序标记 |

## 确认结果

- 测试状态为 Succeeded，且目标邮箱确实收到邮件；
- 默认标识落在预期的那条配置上；
- 实际触发一次邀请或密码找回，确认邮件里的链接指向正确的平台地址。

只做到前两项不够 —— 链接地址错了，用户点进去一样用不了。

## 常见问题

| 现象 | 检查方向 |
| --- | --- |
| 测试一直 Failed | 出站端口是否被防火墙或云安全组拦下；加密方式与端口是否匹配 |
| 提示认证失败 | 是否用了登录密码而不是授权码；用户名是否要带完整邮箱地址 |
| 发送成功但收不到 | 收件方垃圾箱、服务商投递记录、发件域名 SPF/DKIM 配置 |
| 邮件里的链接打不开 | `Settings → Access & Sign-in` 的平台访问地址是否与实际访问地址一致 |
| 想把默认配置删掉 | 默认配置不能直接删除；先建好并验证一条替代配置，切换默认后再删 |

::: tip 不要把密码贴进截图或工单

排查时提供的截图请遮挡 Password 字段。SMTP 凭据泄露后，任何人都能借你的发件身份发信。

:::
