# 容灾演练

入口：**Drill**。

演练的目的只有一个：**在不影响生产的前提下，证明某个恢复点真的能恢复出可用业务**。

任务成功只能说明备份流程走完了。演练验证的是"恢复之后业务能不能跑"。

## 演练与恢复的区别

| | 演练 | 恢复 |
| --- | --- | --- |
| 目的 | 验证能力 | 处理真实故障 |
| 范围 | 隔离环境 | 业务目标环境 |
| 风险 | 低，可反复做 | 高，可能覆盖现有资源 |
| 频率 | 定期 | 按需 |

## 演练前

- [ ] 集群 online，Agent 正常
- [ ] 存在可用的恢复点
- [ ] 目标范围是隔离的，不会碰到生产资源
- [ ] 恢复缓存预检通过（见下）

## 恢复缓存预检

演练提交恢复之前，Agent 会读取实际 ConfigMap 和 StorageClass 做预检：

| 预检结果 | 行为 |
| --- | --- |
| 未启用缓存 | 记录使用临时磁盘，继续 |
| 缓存配置有效 | 记录 StorageClass、阈值和缓存上限，继续 |
| 已启用但配置不可用 | 在创建 Restore 之前以 `RESTORE_CACHE_PREFLIGHT_FAILED` 返回 |

预检失败不能被静默忽略——Velero 在运行时创建缓存 PVC 失败**不会**自动回退临时盘。

预检可能失败的情形：StorageClass 缺失、没有动态 provisioner、`reclaimPolicy` 不是 `Delete`、ConfigMap 无法解析。详见[Velero 恢复缓存](/docs/operations/restore-cache)。

## 演练要校验什么

不要只看任务标签变绿。按这个顺序核：

1. **工作负载**：Deployment/StatefulSet 是否就绪，副本数、镜像版本是否符合预期。
2. **PVC**：是否绑定成功，容量和 StorageClass 正确。
3. **应用数据**：连进应用看数据，抽查关键记录或文件。
4. **对外服务**：Service/Ingress 是否可用（在隔离范围内验证）。

::: warning 部分成功也是失败

Velero 的恢复可能出现"部分完成"——大部分资源恢复了，少数失败。这类情况在任务状态上可能看起来正常，必须逐项核对资源清单。

:::

## 演练结果怎么用

| 结果 | 含义 | 下一步 |
| --- | --- | --- |
| 全部通过 | 恢复能力已验证 | 记录时间点，按周期复演 |
| 工作负载异常 | 镜像、配置或依赖缺失 | 补齐依赖，重新演练 |
| 数据不完整 | 备份范围或一致性有问题 | 检查保护范围与存储 |
| 预检失败 | 集群存储能力不满足 | 调整 StorageClass 或缓存配置 |

把每次演练的时间、恢复点、结果记录下来。真出故障时，这份记录比任何文档都有说服力。
