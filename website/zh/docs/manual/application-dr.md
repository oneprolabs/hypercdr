# 应用容灾保护

入口：**DR → Application DR**。

这是把前面几个基础资源组装起来的地方：**哪些应用受保护、备份写到哪里、恢复到哪个集群、按什么节奏执行**。

## 页面三阶段

| 阶段 | 展示内容 |
| --- | --- |
| 源应用 | 当前可保护的源 namespace 及其状态 |
| 保护配置 | 已建立的保护关系、绑定的存储与策略 |
| 目标侧状态 | 目标集群的恢复状态与最近一次恢复情况 |

## 配置流程

1. 选择源 namespace（可多选）。
2. 启动保护向导。
3. 依次选择**范围、目标、存储、策略**。
4. 确认后保存，回到列表核对保护状态。

存储和策略如果还没建，可以在向导里直接创建。向导与管理页复用创建界面，成功后重新加载并选中新增记录。

## 多 namespace 怎么选

多 namespace 时有两种选择：**独立保护**或**合并保护**。

| 方式 | 适用 | 代价 |
| --- | --- | --- |
| 独立 | 应用边界清晰，各自恢复 | 配置数量多，恢复点分散 |
| 合并 | 多个 namespace 属于同一业务，需要一起恢复 | 恢复粒度变粗，单点失败影响整组 |

::: danger 别把范围理解错

**不要把多个应用的恢复范围误认为同一个 namespace。** 一个应用可能跨多个 namespace，也可能多个应用共用一个 namespace。恢复范围选错，演练时才会暴露，而那时已经在处理故障了。

:::

## 目标集群怎么定

保护流程需要源集群**和**目标集群。同一个集群是否适合作为恢复目标，要结合具体应用和恢复配置判断——技术上能选，不代表业务上合适。

判断依据包括：目标集群的存储类、节点架构、网络策略、以及目标 namespace 是否已被占用。

## 保存成功之后

保存只代表配置写入了数据库。真正生效需要：

- [ ] 策略调度到点后产生任务
- [ ] 任务成功，`Restore Points` 出现恢复点
- [ ] 目标侧状态更新
- [ ] 做一次[演练](/docs/manual/drill)确认能恢复

## 常见配置错误

| 现象 | 原因 |
| --- | --- |
| 向导里选不到源 namespace | 集群未上报清单，或集群 offline |
| 保存后没有任务产生 | 策略未生效、未到调度时间、保护未启用 |
| 任务失败提示存储错误 | 存储凭据或集群侧网络问题 |
| 恢复时资源冲突 | 目标 namespace 已有同名资源，或资源映射未核对 |
