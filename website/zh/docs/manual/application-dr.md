# 应用容灾保护

入口：**DR → Application DR**。

本页把前述基础资源组合为一套保护配置，涵盖**受保护的应用、备份写入位置、恢复目标集群和执行节奏**。

## 页面三阶段

![应用保护的三个操作阶段](/images/user-guide/protection-stages.png)

| 阶段 | 展示内容 |
| --- | --- |
| 源应用 | 当前可保护的源 Namespace 及其状态 |
| 保护配置 | 已建立的保护关系、绑定的存储与策略 |
| 目标侧状态 | 目标集群的恢复状态与最近一次恢复情况 |

## 配置流程

1. 选择源 Namespace（可多选）。
2. 启动保护向导。
3. 依次选择**范围、目标、存储、策略**。范围有 Default 和 Custom 两档，见下节。
4. 确认后保存，回到列表核对保护状态。

存储和策略尚未创建时，可以在向导中直接创建。向导与管理页复用同一套创建界面，创建成功后页面重新加载并选中新增记录。

## 资源范围：Default 与 Custom {#resource-scope}

向导里的**范围**决定哪些资源进入备份和恢复，有两档：

| 档位 | 选什么 | 适用 |
| --- | --- | --- |
| Default | 整个 Namespace 的完整备份范围 | 大多数场景，不需要逐类挑资源 |
| Custom | 在当前 Namespace 里按资源类型勾选 | 只需要部分类型，或要排除特定类型 |

### Custom 的行为

- 只列**当前 Namespace 里实际存在对象**的资源类型，同时给出对象数量和类型分类；
- 每一行独立可勾选，初始全选；
- 不会把集群级资源加进你的自定义选择；
- 一次保护多个 Namespace 时走完整备份范围，不提供 Custom。多 Namespace 想细到类型，要拆成多个保护配置。

打开 Custom 时先用上一次成功扫描的结果，同时在后台刷新。刷新失败不会把你已经选好的范围重置回 Default，也不会丢掉已勾选项。

::: warning 依赖校验不是备份范围的保证

Custom 只回答「哪些 Namespace 资源类型进入备份或恢复范围」。目标环境能不能接住这些资源，属于[接管](/docs/manual/takeover)前的就绪度评估，不是这里的承诺。

:::

两个容易误判的地方：

- **空结果不等于没有资源。** 扫描为空会清掉该 Namespace 的缓存条目，其他 Namespace 的目录仍然可用。
- **Event 和平台托管的聚合 API 会出现在列表里。** 它们被单独标出分类，可以手动排除；平台不会按 API 组或资源名悄悄剔除。

## 多 Namespace 的保护方式

多 Namespace 时有两种选择：**独立保护**或**合并保护**。

| 方式 | 适用 | 代价 |
| --- | --- | --- |
| 独立 | 应用边界清晰，各自恢复 | 配置数量多，恢复点分散 |
| 合并 | 多个 Namespace 属于同一业务，需要一起恢复 | 恢复粒度变粗，单点失败影响整组 |

::: danger 恢复范围与 Namespace 不是一一对应

**不要把多个应用的恢复范围误认为同一个 Namespace。** 一个应用可能跨多个 Namespace，也可能多个应用共用一个 Namespace。恢复范围选择错误通常要到演练时才暴露，此时可能已在处理故障。

:::

## 目标集群的选择

保护流程需要源集群**和**目标集群。同一个集群是否适合作为恢复目标，需要结合具体应用和恢复配置判断：技术条件满足，业务上未必合适。

判断依据包括目标集群的存储类、节点架构、网络策略，以及目标 Namespace 是否已被占用。

## 保存成功之后

保存只表示配置写入了数据库。配置生效需要满足以下条件：

- [ ] 策略调度到点后产生任务
- [ ] 任务成功，`Restore Points` 出现恢复点
- [ ] 目标侧状态更新
- [ ] 做一次[演练](/docs/manual/drill)确认能恢复

## 常见配置错误

| 现象 | 原因 |
| --- | --- |
| 向导中选不到源 Namespace | 集群未上报清单，或集群 offline |
| 保存后没有任务产生 | 策略未生效、未到调度时间、保护未启用 |
| 任务失败提示存储错误 | 存储凭据或集群侧网络问题 |
| 恢复时资源冲突 | 目标 Namespace 已有同名资源，或资源映射未核对 |
