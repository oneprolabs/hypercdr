# 术语表

## 平台与部署

| 术语 | 含义 |
| --- | --- |
| **中控 / 控制面** | 提供界面和 API 的平台服务，由 Edge、前端、API、PostgreSQL 等组成 |
| **Edge** | 在 12443 终止 TLS 并转发请求的 Nginx 层 |
| **蓝 / 绿** | 两套并行的应用环境，升级时通过切换流量完成发布 |
| **活动颜色** | 当前正在接收流量的那一套（蓝或绿） |
| **安装目录** | 默认 `/var/lib/hypercdr`，含 `.env`、TLS、Compose、版本清单 |
| **版本清单 / manifest** | 固定各组件版本的文件，安装和升级时激活 |
| **升级执行器** | 宿主机上的 systemd 服务，读取升级任务并调用蓝绿脚本 |
| **注册执行器** | 平台内部服务，用 kubeconfig 执行 Install for me 注册 |

## 集群与组件

| 术语 | 含义 |
| --- | --- |
| **Agent** | 部署在业务集群内的组件，出站连接平台并执行任务 |
| **Velero** | 原生 Kubernetes 与 CCE 使用的备份恢复组件 |
| **OADP** | OpenShift 的 Velero 发行版，OpenShift 集群走这条路径 |
| **Node Agent** | Velero 的节点级组件，负责文件系统备份与恢复 |
| **Kopia** | Velero 使用的仓库与数据移动实现 |
| **Data Mover** | CSI 快照数据移动机制，恢复时用到恢复缓存 |
| **恢复缓存** | 恢复阶段使用的临时 PVC 策略，见 [Velero 恢复缓存](/docs/operations/restore-cache) |
| **BSL** | BackupStorageLocation，Velero 侧的对象存储位置 |

## 业务对象

| 术语 | 含义 |
| --- | --- |
| **组织 / tenant** | 资源隔离边界，接口与数据库中称 `tenantId` |
| **源集群 / 目标集群** | 被保护的一方 / 恢复落地的一方 |
| **存储** | 对象存储配置，备份数据的落点 |
| **策略** | 保护计划与保留规则的组合 |
| **应用容灾** | 源 namespace + 目标 + 存储 + 策略的组合配置 |
| **任务** | 一次备份或恢复的执行记录 |
| **恢复点** | 某次成功备份产出的可恢复时间点 |
| **演练 / Drill** | 在隔离范围验证恢复是否可用 |
| **恢复 / Recovery** | 把恢复点还原到目标环境 |

## 版本与许可

| 术语 | 含义 |
| --- | --- |
| **社区版 / ce-** | 标签形如 `ce-v0.0.13`（当前版本见仓库根目录 `VERSION`） |
| **企业版 / ee-** | 标签形如 `ee-v0.0.8`，独立递增 |
| **community.lock** | 企业版固定社区版源码提交和组件版本的锁文件 |
| **就地升级** | 平台自身通过蓝绿切换版本 |
| **组件升级** | 集群内 Agent/Velero/OADP 的版本升级，独立于平台升级 |

## 容易混淆的三组词

| 对比 | 区别 |
| --- | --- |
| 平台升级 vs 组件升级 | 前者升级控制面，后者升级集群内组件，**互不自动跟随** |
| 流量回滚 vs 数据库回滚 | 前者切回旧版本应用，后者需要还原备份，**迁移不会自动撤销** |
| 任务成功 vs 恢复可用 | 前者是执行流程走完，后者要靠演练验证 |
