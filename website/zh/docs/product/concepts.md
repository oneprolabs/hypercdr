# 核心概念

平台的页面结构基本是这些概念的顺序：先有组织，组织下有集群和存储，集群上配置策略，策略产出任务和恢复点，恢复点用于演练和恢复。

## 概念一览

| 概念 | 含义 | 界面位置 |
| --- | --- | --- |
| 组织 | 资源隔离边界。一个账号只属于一个组织 | Settings → Organization |
| 集群 | 已注册的 Kubernetes / CCE / OpenShift 集群 | Configuration → Clusters |
| 存储 | 对象存储地址、bucket 与凭据 | Configuration → Storage |
| 策略 | 保护计划、保留规则等选项 | Configuration → Policies |
| 应用容灾 | 源 namespace、目标端与存储的组合保护配置 | DR → Application DR |
| 任务 | 一次备份或恢复的执行记录 | Backup & Recovery Tasks |
| 恢复点 | 某次成功备份产出的可恢复时间点 | Restore Points |
| 演练 | 在隔离范围验证恢复是否可用 | Drill |
| 恢复 | 恢复任务的能力与任务记录类型；可用入口是 Drill 和 Takeover | Backup & Recovery Tasks |
| 接管 | 按容灾切换流程把业务切到目标端，需先通过校验和变更审批 | Takeover |
| 同步 / 备份 | 一次数据同步或备份执行，由 Agent 完成并产出恢复点 | Tasks |

## 关系模型

```text
组织
├── 集群（源 / 目标，按集群类型区分安装路径）
├── 存储（对象存储，可被多个策略引用）
├── 策略（计划 + 保留规则）
└── 应用容灾
    ├── 源 namespace 范围
    ├── 目标集群
    ├── 存储
    └── 策略
        └── 任务 → 恢复点 → 演练 / 恢复
```

## 几个容易混淆的点

**源集群和目标集群是两件事。** 保护流程需要源集群和目标集群。同一个集群是否适合作为恢复目标，要结合具体应用和恢复配置判断，不能默认成立。

**存储保存成功不等于可用。** 存储配置只是个引用，真正的访问权限和数据路径只有实际备份和恢复才能验证。

**namespace 范围不等于应用边界。** 一个应用可能跨多个 namespace，也可能多个应用共用一个 namespace。选择恢复范围时按业务需要判断，独立还是合并需要提前定好。

**任务成功不等于恢复可用。** 任务状态只说明执行流程走完，恢复是否真的可用要看演练结果和应用校验。

**平台管理员不是组织成员。** 平台管理员的跨组织权限只用于用户、组织等平台管理，不授予跨组织业务资源访问权。业务页面不提供组织切换。

## 恢复点与恢复的边界

- **保护配置**把源集群、应用/namespace、策略和存储仓库组合成一条可执行关系；
- **同步/备份**由 Agent 执行存储准备、备份或状态推进，平台接收事件并建立或更新恢复点；
- **恢复点**由源集群、保护配置、备份任务和 Velero 备份名共同确定，可查看状态、保留信息和内容清单；
- **Restore** 是恢复任务的能力与记录类型，当前已核验的恢复点操作入口是 **Drill** 和 **Takeover**，没有独立的 Restore 创建按钮。
- **Drill** 只向隔离目标验证恢复链路，**Takeover** 才是有审批的容灾切换。

恢复点处于创建中、来源不匹配、保护配置已删除或仓库不可访问时，不应启动恢复。任务成功后仍要检查目标工作负载、PVC、Service、应用健康和数据；删除平台里的恢复点记录，也不等于立即擦除对象存储中的全部数据。

## 配置边界与安全责任

用户、组织、策略、任务、恢复点等中控元数据保存在 PostgreSQL，秘密字段由 `HCDR_SECRET_KEY` 保护。

因此一份完整的平台备份必须同时保留：**数据库、`HCDR_SECRET_KEY`、TLS 文件、`.env`、版本清单和对象存储访问配置**。只备份数据库而没有密钥，可能无法解密存储凭据；只保留对象存储而没有中控元数据，也无法恢复完整的管理面。

登录挑战支持图片验证码和 Cloudflare Turnstile：图片验证码为四位数字/字母且字母不区分大小写；Turnstile 需要有效 key、浏览器可访问 Cloudflare 控件、服务端能出站校验。实际模式以安装目录 `.env` 为准。
