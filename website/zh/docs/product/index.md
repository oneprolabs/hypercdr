# 产品概览

HyperCDR 是面向 Kubernetes 与 OpenShift 的**容器容灾平台**，在 Velero 与 OADP 之上提供一层管理能力，把集群管理、保护策略、恢复点、演练和恢复任务组织成可重复的流程。

控制台不负责备份数据的传输。实际的数据搬运由运行在业务集群中的集群 Agent 完成：Agent 主动向外连接平台，协调 Velero（原生 Kubernetes、Huawei CCE）或 OADP（OpenShift）执行任务。

平台的处理流程是「保护 → 验证 → 恢复」：管理员登记集群和存储，选择需要保护的应用，按策略产出恢复点，再用 Drill 验证恢复结果；需要正式接管时，执行 Takeover 流程。

HyperCDR 面向 Kubernetes 应用保护，物理机、VMware 无代理、公有云专用接口和跨平台迁移不在当前版本的能力范围内。

## 常见问题与对应做法

| 常见痛点 | HyperCDR 的做法 |
| --- | --- |
| 每个集群各装一套备份工具，计划散落在不同地方 | 一个控制台注册多个集群，保护策略集中定义 |
| 备份任务成功，但无法判断能否恢复 | 用演练在隔离范围验证恢复，检查工作负载、PVC 和应用数据 |
| 跨集群恢复依赖文档和人工记录 | 建立源端与目标端的映射关系，从策略直接进入恢复流程 |
| 平台和集群组件版本互相不匹配 | 通过版本清单固定组件版本，平台与集群升级分别确认 |
| 多团队共用一个平台，资源边界不清 | 账号属于组织，业务资源按组织隔离 |

## 适用场景

- Kubernetes 集群的应用级备份与恢复；
- 以对象存储作为备份介质的跨集群恢复；
- 通过 Drill 在隔离目标中验证恢复点可用性；
- 对恢复任务、同步任务和容灾任务统一跟踪进度、状态与日志；
- 需要多组织隔离、成员管理和平台级运维权限的私有化部署。

| 使用目标 | 推荐做法 |
| --- | --- |
| 日常保护 | 为应用建立保护配置，按策略执行同步/备份并检查最新恢复点 |
| 恢复可用性验证 | 在与生产隔离的目标 Namespace 执行 Drill，检查工作负载、PVC、Service 和业务数据 |
| 正式接管 | 评审恢复点、目标集群和资源映射后执行 Takeover 流程，并完成应用级验收 |
| 多团队协作 | 用组织、成员和角色权限隔离业务资源，按职责分配平台管理与容灾操作 |

实际支持范围取决于 Kubernetes 发行版、Agent 版本、Velero/OADP 路径、CSI/存储驱动和对象存储兼容性，部署前应结合[适配范围](/docs/reference/support-scope)与现场验证确认。

## 核心能力

- **集群接入**：注册 Native Kubernetes、Huawei CCE 与 OpenShift 三类集群，采集节点和 Namespace 清单，查看 Agent 在线状态。
- **存储与保护策略**：配置对象存储地址、bucket、凭据和集群侧参数，再定义调度、资源范围与保留规则。
- **同步与恢复点**：按策略执行同步或备份，平台接收事件并建立恢复点记录。
- **应用容灾**：按源 Namespace 组织保护范围，配置目标端与存储，跟踪目标侧恢复状态。
- **Drill 容灾演练**：在隔离目标验证恢复链路，检查工作负载、PVC、Service 和应用数据。
- **Takeover 接管**：按容灾切换流程执行接管，需先通过校验和变更审批。
- **身份与组织隔离**：社区版支持邮箱注册、Google 登录和组织邀请，业务资源按组织隔离。
- **升级与回滚**：平台以蓝绿方式运行，升级切换流量并记录活动版本；回滚只恢复应用流量和版本清单。

## 平台界面结构

社区版控制台的一级入口包括 Dashboard、DR、Configuration、Operations 和 Settings，页面可见范围受账号权限影响；页面未显示，也不代表可以绕过权限直接调用 API。

| 入口 | 覆盖内容 |
| --- | --- |
| Dashboard | 组织资源、保护健康、同步与恢复活动以及当前告警 |
| Configuration | Clusters、Storage、Policies、Tag Management |
| DR | Application DR、Restore Points、Backup & Recovery Tasks |
| Operations | 平台侧的运行、升级与维护入口 |
| Settings | 个人、组织、平台设置与平台升级 |

所有业务资源按组织（tenant）隔离。平台管理员可以管理用户和组织，但不能通过 URL、组织 ID 或请求头切换到其他组织的集群、存储、策略、应用、任务或恢复点。

## 与 Velero、OADP 的关系

HyperCDR 保留构建所需的 Velero 源码（`third_party/velero/`），并在注册集群时安装版本匹配的组件：

- 原生 Kubernetes 与 Huawei CCE 使用社区 Velero 路径；
- OpenShift 使用 OADP 专用组件与安装路径。

Velero 和 OADP 的能力边界会直接影响 HyperCDR 的支持范围。存储插件、CSI 快照和节点架构的限制依然有效，平台不绕过这些限制。三类集群的注册差异见[控制台架构](/docs/product/architecture#三类集群的注册差异)。

## 产品边界

- 平台不自动安装 Docker，宿主机必须预先准备运行时；
- 平台不会替用户配置 DNS、外部反向代理、公开证书、对象存储或集群网络策略；
- 平台升级与集群 Agent、组件的升级相互独立，需分别检查版本与任务结果；
- 自动生成的 TLS 证书用于启动 HTTPS，浏览器不会将其视为受信任的公开证书；
- 源码中的适配代码、构建资产或实验路径只能说明该能力已实现，是否通过认证要按发行版、驱动和拓扑分别确认。

## 社区版与企业版

社区版标签采用 `ce-v主版本.次版本.补丁版本`，企业版采用 `ee-v主版本.次版本.补丁版本`，两者独立递增。

企业版通过 `community.lock` 固定社区版源码提交和已发布的组件版本，修改企业版版本不会自动改变这个依赖。仓库提供公开的扩展边界，企业扩展设计与社区版功能相互独立，社区版不包含全部企业实现。
