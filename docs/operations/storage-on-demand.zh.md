# 对象存储按需访问

支持此策略的 Velero 与 Agent 配套部署后，HyperCDR 管理的 BackupStorageLocation 使用 `hypercdr.io/storage-access=on-demand-v1`，并将 `validationFrequency`、`backupSyncPeriod` 设置为 `0s`。未标记的存储位置保留上游行为，旧版本滚动升级期间不假定具备该能力。

## 任务行为

- 空闲期不进行存储可用性轮询、备份目录同步或周期仓库维护；控制器仍可读取 Kubernetes 对象，这不访问对象存储。
- 备份前执行一次存储校验，Drill / 恢复前执行存储校验并只导入选中的备份及其卷备份元数据，不扫描全部恢复点。
- 预检失败或超时终止任务，不继续提交 Backup / Restore。预检最长两分钟，排队时间包含在内。
- Kopia 在实际任务打开仓库时读取所需索引，复用已有节点缓存，不新增独立的空闲索引刷新任务。
- 成功备份后仅对已到维护周期的仓库请求维护；存在其他备份或恢复时跳过。维护失败记录警告，不将已成功的备份改为失败。Drill 前不执行维护。
- 支持缓存的维护 Job 继承 Node Agent 的节点缓存配置，并使用独立缓存租约。节点目录是每节点的配置，不是所有节点共享一个磁盘目录。

## 能力与确认

Velero Deployment Pod 模板必须声明 `hypercdr.io/storage-on-demand-supported=v1`，且 `hypercdr.io/storage-on-demand-image` 与实际镜像完全一致。仅支持的新镜像可声明该能力，不得给旧镜像手工添加标记来替代升级。发布默认镜像为 `velero-v1.18.2-hcdr.6`，发布时须实际构建并推送该镜像。

Agent 使用带 UTC 时间的一次性请求注解，控制器回写完成令牌与结果。过期或已完成请求不会再次触发访问。恢复仓库的初始化仍属于任务必要访问，不等于全仓扫描。

由于空闲期不校验，存储位置的 Available 状态代表上次校验结果，不代表实时连通性。显式存储测试和任务前校验仍会访问对象存储。每日计划容量采集、用户刷新容量和业务任务也可能产生必要访问，不应归类为空闲扫描。

## 验证

检查所有受管 BSL 的策略和两个周期、实际镜像能力绑定、节点缓存挂载及滚动更新完成状态。分别观测空闲窗口、备份、Drill 的对象存储网络请求，确认维护只在成功备份后按需启动。网络观测必须覆盖控制器与工作节点，并排除期间的计划任务；不要仅依据配置值认定流量归零。
