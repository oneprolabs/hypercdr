# 首次使用：从集群注册到恢复验证

先按[安装指南](../deployment/deployment-guide.zh.md)完成登录。使用测试 namespace 验证完整流程后再保护业务。

## 1. 注册集群

进入顶部 Configuration → Clusters，选择注册操作与 Native Kubernetes、CCE 或 OpenShift 类型。准备页面要求的 kubeconfig。Install for me 适用于平台执行器能访问集群 API 的环境；否则在可访问集群的主机使用 Run command。按页面第一步准备文件，再执行当前生成的命令。不要把访问 token 或 kubeconfig 分享到公开 issue。

安装完成后确认集群 online、节点和 namespace 清单已上报。保护流程需要源集群和目标集群；同一集群是否适合作为恢复目标需结合具体应用和恢复配置判断。

## 2. 准备存储和策略

在 Configuration 的 Storage 配置对象存储地址、bucket 和凭据，确认集群侧可访问存储。Policies 设置保护计划及保留等选项。也可在新的保护向导中创建这些资源：向导与管理页复用创建界面，成功后重新加载并选中新增记录。

不要仅以资源保存成功判断存储可用；实际备份与恢复才验证访问权限和数据路径。

## 3. 配置应用保护

进入 Disaster Recovery → Application DR。三阶段分别展示可保护的源应用、保护配置及目标侧恢复状态。选择源 namespace，启动保护向导，依次选择范围、目标、存储和策略。多 namespace 时按业务需要选择独立或合并；不要把多个应用的恢复范围误认为同一 namespace。

## 4. 核验备份和恢复

触发或等待策略任务，在 Backup & Recovery Tasks 查看执行状态及详情；确认成功后在 Restore Points 检查恢复点。使用 Drill 在隔离范围验证恢复，并检查工作负载、PVC 和应用数据，而非仅看任务成功标签。实际 Recovery 前核对目标与资源映射，避免覆盖现有业务。

Dashboard 区分平台概览与所选集群概览；集群选择和时间范围用于对应指标，不能将所有指标都理解为平台总量。任务失败时查看错误和日志，不使用示例数据解释结果。

## 5. 用户设置与清理

登录页固定深色；首次登录默认浅色，用户主题偏好保存到服务端，后续登录采用个人设置。用户显示时间使用选定时区，服务端时间与调度基础使用 UTC。

注销集群使用集群卡片菜单的标准注销流程，核对平台记录与集群资源清理结果。卸载平台不是注销所有业务集群，也不是删除对象存储备份。
