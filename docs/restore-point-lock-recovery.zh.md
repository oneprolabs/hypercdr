# 恢复点替换锁的失败恢复

配额满时，备份先预留并锁定候选恢复点，不立即删除。同步失败或取消后，
平台在任务状态更新事务内释放尚处于 `reserved` 的预留，无需依赖结束时间标记。

调度器定期检查已失败或取消任务的残留预留；API 重启后继续检查。
下次备份在同一保护计划的事务锁内先执行相同检查，再按保留及配额规则选择候选。
释放操作幂等，只移除属于该预留任务的锁，不删除恢复点、不修改保留标记。

新建同步任务时，在保护计划行锁内检查是否已有非终态同步或未完成的恢复点替换。
如存在则拒绝新建；手动请求的竞争冲突返回 HTTP 409，定时调度留待后续周期处理。
多命名空间计划使用一个携带全部命名空间的同步任务，不拆成多个并行同步任务。

运行中的任务不能仅因锁持续较久就释放，必须先经任务故障处理确认为失败或取消。
`data_ready`、`deleting` 阶段不能直接释放：旧恢复点可能已开始实际删除，
需要继续确认清理结果及发布新恢复点。清理失败或取消后按退避机制重试。
清理任务记录缺失或状态未知时保持锁定，不能冒险允许并发替换。
