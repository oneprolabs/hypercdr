# Security Policy

Do not report security vulnerabilities in public GitHub issues. Contact the
HyperBDR maintainers privately and include affected versions, reproduction
steps, impact, and any suggested mitigation.

Never attach production credentials, kubeconfigs, private keys, access tokens,
database dumps, object-storage credentials, or customer data to a report.

Security fixes should preserve tenant isolation, redact secrets from logs, and
include regression coverage before release.
